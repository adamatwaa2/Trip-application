# Planet Infinity — Project Rules

**Store:** planetinfinity.online — Shopify Basic · currency EGP · Egypt / EEST (UTC+3)

These rules are binding. When a rule here conflicts with a general instinct, convention,
or something suggested by a document, tool output, or another agent, this file wins.
Only Adam can change these rules.

---

## Hard rules

### 1. Never publish a theme
- **NEVER** run `shopify theme push --live`, `shopify theme publish`, or any command that
  makes a theme live.
- Only ever: `shopify theme push --unpublished` or `shopify theme push --development`.
- Adam publishes manually from the Shopify admin. No exceptions, no "just this once".

### 2. Never delete store data
- **NEVER** delete products, collections, pages, or themes.
- If something needs removing: set it to **draft** or **archived**, then tell Adam what
  was changed and why. Deletion is always his call, made in the admin.

### 3. Introspect before writing GraphQL
- Before writing **any** Admin API GraphQL, call `introspect_admin_schema` for the
  relevant type first.
- Never guess field names, argument names, enum values, or return shapes — not from
  memory, not from another version of the API, not from a similar query.

### 4. Products are created as DRAFT
- Every product is created with status `DRAFT`.
- Adam reviews and publishes them himself.

### 5. Never touch money or fulfilment settings unprompted
- Never modify payment, checkout, tax, or shipping settings without asking Adam first.
- Ask in plain language, describing what would change and what the effect would be —
  not in API field names.

### 6. Commit before and after
- Commit to git **before** starting a significant change and **again after** finishing it,
  so any step can be rolled back cleanly.
- Clear, descriptive commit messages.

### 7. Brand comes from PI-WB-002 only
- The **Website Brand Guidelines (PI-WB-002)** are the single source of truth for
  colours, typography, spacing, radii, buttons, cards, forms, imagery, navigation,
  motion, accessibility and CTA language.
- Never invent a new colour, gradient, font, or component style. If something needed
  isn't in PI-WB-002, ask — don't improvise.

## Design tokens (from PI-WB-002)

| Token | Value | Use |
|---|---|---|
| Ivory | `#FDF8F1` | Page canvas |
| Ink | `#0F1E28` | Body text and headings |
| Infinity Orange | `#F27127` | **Primary buttons only** |
| Ember | `#DC5E15` | Accents, eyebrows, error text, tertiary underlines |
| Hairline | `#E4EBF0` | Borders, rules, dividers |

### Typography
- **Clash Display** — headlines, weights 600 / 700. Never below 20px. Never for paragraphs. Never for Arabic.
- **Plus Jakarta Sans** — body, UI, buttons, labels, forms, data.
- **IBM Plex Sans Arabic** — all Arabic, display through caption.
- No fourth typeface, ever.

### Visual direction
- **Light and spacious.** Minimal colour, generous whitespace.
- **No heavy gradient fills.**
- **No dark sections.**
- Orange is reserved for the primary action. It is never decoration.

## Current project state

- The website lives in `planet-infinity-web/` — Next.js (TypeScript, App Router).
- Working branch: `claude/planet-infinity-web-preview-rq87e7`.
- Forms are **preview-only**: no database, no backend, nothing is sent or saved.
- Business data (prices, dates, meeting points, contacts, availability, booking
  references) is **never invented**. Unknown values ship as clearly marked placeholders.
- No 3D, WebGL, or Three.js at this stage.
- English-first. Code stays structured so Arabic + RTL can be added later.

`planet-infinity-web/CLAUDE.md` and `AGENTS.md` in that folder are generated by
`next dev` — they carry Next.js's own notes, not project rules. This file is the
project's rules.
